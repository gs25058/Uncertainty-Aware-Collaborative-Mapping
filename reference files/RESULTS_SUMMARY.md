## 1. 연구 목표와 현재 위치

### 목표
카메라(+IMU)만 탑재한 드론 3대가 **UWB 상대측위**로 묶여 협업하여, GPS 불가 실내에서
**항법용 3D 점유지도**를 구축한다. 핵심 기여는 두 갈래다.

1. **협업 정합의 불확실성 Σ를 지도 생성 과정에 전파**하여 항법 안전성 확보
2. **협업 규모가 지도 품질에 기여하는 인과를 정량적으로 규명**

계획서가 규정한 제약: anchor-free(재난 현장 상정), 로봇 간 시각 특징 연관 없음,
LiDAR 없음.

## 2. 시스템 구성

### 파이프라인

```
[드론k 카메라+IMU]
      ↓  VINS-Fusion (로컬 프레임 L_k, metric SE(3))
[VIO 궤적 T^k_n]
      ↓  GTSAM pose graph: odometry + inter-agent UWB range + gauge prior
[융합 자세 T^k_n(world)]  +  [Σ^k_n = marginal covariance H⁻¹]
      ↓                          ↓
[스테레오 SGBM 깊이 Z, σ_Z]      ↓
      ↓                          ↓
[역투영 → 세계 좌표 점군]  ←──────┘
      ↓  가중 log-odds + 안전 비대칭
[3D occupancy: free / occupied / unknown]
```

### 구현 도구

| 단계 | 도구 | 비고 |
|---|---|---|
| VIO | VINS-Fusion (C++) | conda RoboStack ROS1 Noetic, 알고리즘 무수정 |
| 융합 | GTSAM (Python) | `BetweenFactorPose3` + custom range factor |
| 깊이 | OpenCV SGBM (Python) | f·B = 21.7, 5 m 절단 |
| occupancy | OctoMap `updateNode()` 직접 호출 (Python) | C++ 무수정 |
| 평가 | 자체 스크립트 + mocap | MILUV 로더 규약 준수 |

### 주요 파일

| 파일 | 역할 |
|---|---|
| `covor/fusion.py` | 그래프 구성, 조건 ablation(`inter_pairs`/`anchor_robots`), 게이지 |
| `covor/factors.py` | range factor, gravity prior, pose prior |
| `covor/data.py` | VINS 로더, mocap 로더(정제 규칙 적용) |
| `covor/occupancy.py` | `StereoDepth`, `OccupancyBuilder` (가중 log-odds) |
| `scripts/fuse_and_dump.py` | 융합 실행 → 자세 + tr(Σ) 산출 |
| `scripts/build_occupancy.py` | 지도 생성 드라이버 |
| `scripts/compare_weighting.py` | weighted vs uniform ablation |
| `scripts/gt_pose_control.py` | mocap 기준선 지도 |
| `tests/test_ray_traversal.py` | 회귀 테스트 6개 (셀별 log-odds **값** 비교) |

VINS 산출물은 저장소 밖 `ws/vins_ws/run/out/<seq>/<robot>/vio.csv` (git 미추적).

## 3. Phase 2 — UWB-VO 정합 (CoVOR-SLAM 재현)

### 3.1 재현 범위

CoVOR-SLAM(Lee et al. 2023)을 코드 없이 GTSAM으로 재현. 논문 대비 정렬 상태는
`FAITHFUL_REPRODUCTION.md`에 체크리스트로 기록. 주요 편차 2건:

- **초기 프레임 정렬**: 논문은 ArUco 마커, 우리는 mocap Umeyama (초기값에만 사용)
- **안테나 오프셋**: 논문은 "오프라인 보정 가정", 우리는 MILUV `tags.yaml`의 모멘트암을
  명시 팩터로 처리

Sim(3) 7-DoF는 GTSAM Python이 `Similarity3` 탄젠트 연산을 노출하지 않아
`Pose3` + 스칼라 스케일로 등가 재파라미터화했다. (이후 VINS 전환으로 제거됨 — §5)

### 3.2 융합 악화 미스터리와 진단

**증상**: mono VO보다 UWB를 융합한 결과가 오히려 나빴다. 그래프 목적함수는 감소하는데
mocap 대비 정확도는 악화.

**진단 절차** (`DIAGNOSIS.md`):

1. **51개 설정 스윕** → 튜닝으로 복원 불가 확인. 파라미터 문제가 아님.
2. **H1 (평가 정렬 비대칭) 기각** — 동일 Sim(3) 정렬을 양쪽에 적용해도 악화 실재.
3. **H2 (관측 모델 결함) 부차적** — 앵커 6개 잔차 균일(좌표 오류 없음), 레버암은
   자세 의존 산포(mean≈0, std 0.15), moment-arm 팩터로 ~0.03 m만 개선.
   기존 `range_bias=0.14`는 robot1-only 버그 서브셋에 맞춘 과보정이었음(실제 ~0.05).
4. **gt_range 대조** — 완벽한 거리로도 악화. 즉 코드가 아니라 데이터/기하 문제.

**규명된 원인 2건**:

- **수직 기하 (VDOP)**: 앵커 6개가 전부 ~1.7 m 높이. 완벽한 gt_range로도 수직을
  결정할 수 없다. height 팩터가 보완(zRMSE 0.30→0.05)하나 계획서 범위 밖 확장.
- **UWB 노이즈 체급**: 실측 std 0.22 m가 당시 VO 오차보다 커서 융합이 구조적 손해.

**결정적 증거**: gt_range + moment-arm + height 조합에서 mean 0.160 ≈ VO 0.168.
파이프라인은 정상이고 격차는 전적으로 실측 UWB 품질에서 왔다.

### 3.3 사후 정정 (VINS 시대에 확인)

초기에는 "VO 오차 > UWB RMSE(0.22)일 때만 융합 이득"으로 정리했으나, 이후 측정으로
정정되었다. 그 기준이면 ORB 시대의 ifo002·ifo003은 이득이어야 했는데 실제로는 악화했다.

**검증된 설명**:
- ORB 시대 실패의 주된 원인은 **UWB 연관 89.9% 손실** (타임스탬프/키프레임 매칭)
- 융합 오차의 바닥은 RMSE가 아니라 **계통 bias**가 정한다
  (앵커 bias +0.087 m ≈ 관측된 융합 오차 0.062~0.083 m)

### 3.4 UWB 실측 품질 (mocap 참거리 기준)

| 항목 | 값 |
|---|---|
| 전체 RMSE | 0.22 – 0.24 m |
| bias | +0.05 m |
| std | 0.22 m |
| median &#124;e&#124; | 0.07 m |
| p99 / max | ~0.9 / ~1.8 m |
| inter-agent RMSE | **0.17 m** (bias ≈ 0) |
| anchor RMSE | **0.26 m** |
| 종류별 bias | anchor **+0.087 m**, inter **+0.004 m** |

CSV의 std 컬럼(평균 0.17)은 실제 오차 std(0.22)를 과소평가한다 → 그대로 쓰면 과신.
Huber 커널과 sigma 하한이 필요한 이유가 이 데이터 특성이다.

### 3.5 프론트엔드 베이스라인의 정체 (중요)

"mono-VO 베이스라인"이라 불렀던 것은 순수 오도메트리가 아니라 **loop closing까지
켜진 ORB-SLAM3 풀 모노큘러 SLAM**이었다. `System::MONOCULAR` 생성자가 Local Mapping,
Loop Closing, Atlas 맵 병합을 모두 활성화하고, `SaveKeyFrameTrajectoryTUM`은 그
최적화가 반영된 궤적을 저장한다.

즉 CoVOR가 상정한 "드리프트하는 VO"보다 한 체급 위의 비교군이었다.

**순수 VO 시도는 실패했다** (함정으로 기록):
`loopClosing: 0`은 루프클로저만 끄는 것이 아니라 `mbActiveLC` 하나로 **map merging까지
함께 끈다**. 트래킹 손실이 잦은 드론 영상(ifo002에서 1460회)에서 지도가 ~10조각으로
갈라지고 다시 병합되지 않아, 저장된 궤적이 비행의 **4~15%**만 남았다
(KF 74/20/44 vs 원래 202/307/391). 이 접근은 폐기했다.

## 4. 프론트엔드 전환 — ORB-SLAM3 → VINS-Fusion

### 4.1 전환 동기: 회전 오차

GT 포즈 대조군 실험이 지도 품질의 병목을 프론트엔드로 특정했다.

| | fused (ORB 기반) | GT 포즈 |
|---|---|---|
| 위치 오차 (median) | 0.19 – 0.26 m | 0 |
| **회전 오차 (median)** | **21 – 34°** | 0 |
| 사물 기둥 복원 | 9~10 / 13 | **13 / 13** |
| 방 내부 부유큐브 | 1,101 | **130** |

원인은 구조적이다. **UWB 레인지는 위치만 구속하고, mono 프론트엔드에는 중력 기준이
없다.** 계획서가 원래 상정한 VINS(IMU 중력으로 roll/pitch 절대 관측)면 해소되는 문제다.

### 4.2 관측성 구조의 변화

| 양 | mono | VINS |
|---|---|---|
| 스케일 | 관측 불가 (Sim(3) 필요) | **관측 가능** (가속도 이중적분) |
| roll/pitch | 상대적, 드리프트 누적 | **절대 관측** (중력 벡터) |
| yaw | 관측 불가 | 관측 불가 (드리프트 잔존) |
| 절대 위치 | 관측 불가 | 관측 불가 → **UWB의 역할** |

로봇당 게이지 자유도가 7-DoF(Sim3) → **4-DoF(yaw + 위치 3)** 로 감소.

### 4.3 실행 경로 확보

계획서는 VINS-Fusion을 명시하고 MILUV가 설정 yaml + 런처 + Docker 레시피 + 원본 bag을
제공한다(궤적은 미제공, 우리가 실행). 그런데:

- **Docker 경로 차단**: 데몬 접근 불가(그룹 권한 없음), sudo 없음, 시스템 ROS 없음
- **탈출구**: `micromamba/envs/covins`가 **RoboStack ROS1 Noetic 완본**
  (roscore/roslaunch/rosbag + catkin_make + Ceres·OpenCV·Eigen·SuiteSparse).
  과거 COVINS 작업의 잔존 툴체인이 그대로 사용 가능했다.

빌드 호환 패치 내역은 `VINS_BUILD_NOTES.md`에 기록. 알고리즘·파라미터는 무수정.
bag 재생 시 **`-s 5`로 앞 5초 스킵**이 VI 초기화에 유효했다.

### 4.4 VINS 궤적 결과 (4개, mocap 정제 후 확정값)

| 궤적 | 위치 RMSE | tilt med | yaw med | poses / 시간 | 커버리지 |
|---|---|---|---|---|---|
| zigzag / ifo001 | 0.171 m | 0.87° | 3.94° | 4357 / 290.8 s | 전구간 |
| zigzag / ifo002 | 0.202 m | 0.82° | 0.78° | 4347 | 전구간 |
| zigzag / ifo003 | 0.242 m | 0.60° | 6.00° | 4339 | 전구간 |
| obstacles / ifo001 | 0.104 m | 0.68° | — | 3060 | 전구간 |

출력 ~15 Hz 균일, 큰 gap 없음.

**전환 효과 2건**:

1. **맵브레이크 완전 소멸** — ORB에서 트래킹 손실 1460회로 최악이던 ifo002가 291초
   전 구간을 끊김 없이 추정. IMU가 시각 손실 구간을 propagate한다.
2. **tilt 20~30배 감소** — 21~34° → 0.60~0.87°. IMU 중력 관측이 의도대로 작동.

**주의**: 초기 보고값(0.207/0.231/0.259/0.107)은 `timeshift_ns` 누락 상태의 값이다.
수정 후 zigzag가 −17/−13/−7%, obstacles가 −3% 개선되어, "오프셋이 큰 시퀀스가 더 크게
개선된다"는 사전 예측이 확인되었다.

## 5. 융합 레이어 SE(3) 전환

### 5.1 제거된 Sim(3) 우회

VINS가 metric 궤적을 주므로 계획서 설계(SE(3) 6-DoF)로 복귀했다.

| 대상 | 조치 |
|---|---|
| `Sc(k,i)` 스케일 변수, `scale_prior`, `scale_walk` | 삭제 |
| `odometry_factor` (Python CustomFactor, 유한차분 12회) | **네이티브 `BetweenFactorPose3`** 로 교체 |
| `_num_jac_pose` | 삭제 (연쇄) |
| `align_to_world`의 `umeyama_sim3` | rigid(s≡1), yaw-only 초기화 |

성능 이득: 키프레임당 Python 콜백 12회 → 해석적 야코비안 C++ 팩터.

### 5.2 조사 중 발견된 "조용히 틀리는" 문제 3건

프론트엔드 교체로 새로 생겼거나 드러난 것들이다. 셋 다 에러 없이 잘못된 결과를 낸다.

**(a) body vs camera 프레임**
VINS는 body(IMU) 포즈를 출력하는데 occupancy는 camera 포즈를 기대했다.
`body_T_cam0`의 회전이 거의 90°(cam z축 ≈ body x축)이므로 그대로 넘기면 **모든 깊이
광선이 90° 회전**한다.
→ 상태 변수는 body 포즈 `T_wb`로 두고(VINS 출력·mocap 마커·UWB 모멘트암이 모두 body
기준), occupancy 단계에서만 `T_wc = T_wb · body_T_cam0` 합성.
부수 효과로 모멘트암 `q = p + R·l`이 올바른 프레임에서 적용되게 됐다(기존엔 카메라
회전에 body 레버암을 곱하고 있었다).

**(b) `timeshift_ns` 누락**
MILUV 규약은 `t/1e9 − (timeshift_s + timeshift_ns/1e9)`인데 `timeshift_ns`가 빠져
있었다. zigzag 0.256 s, obstacles 0.067 s의 계통 오프셋.
- 평가 영향: mocap이 조밀해 최근접 매칭은 경고 없이 통과하고 RMSE만 부풀린다.
- 융합 영향이 더 치명적: `range_tol = 0.05 s`이므로 0.256 s 오프셋이면 UWB 연관이
  전량 실패하거나 계통적으로 어긋난다.
- `ws/vins_ws/run/`의 `plot_all.py`·`eval_vio.py`·`plot_vio.py` 3개에도 동일 결함이
  남아 있어 수정/차단했다.

**(c) mocap 기반 초기화** — 목적함수가 아니라 초기 추정치에만 들어가므로 즉시 위험은
아니다. 앵커 기반 초기화로 대체하는 것이 논문 충실성 면에서 나으나 보류(§11).

### 5.3 중력 prior — 물리를 그래프에 인코딩

SE(3) 전환 직후 **tilt가 4~5배 악화**했다(0.64~0.90° → 3.01~4.08°).

**원인**: `BetweenFactorPose3`로 바꾸면서 VINS가 중력으로 측정한 roll/pitch가 상대포즈
변환에서 버려졌다. 6,523개 노드 중 절대 방위 구속은 3개(로봇당 첫 노드)뿐이라 나머지는
체인을 따라 자유롭게 표류한다. 체인 누적 여유는 13 s에 7.5°, 40 s에 13°로, 관측된
3~6° 배회가 이 자유 대역 안에 정확히 들어간다.

**UWB는 tilt를 볼 수 없다**: 레버암 |l| = 0.231 m에서 5° 기울여도 태그는 0.020 m
이동 — UWB 노이즈 플로어(0.05 m 미만)에 묻힌다.

**진단 근거**: tilt 오차가 체인을 따라 단조 증가하지 않고 **처음부터 3°대로 뛴 뒤
배회**했다. 단일 앵커에서의 느린 드리프트가 아니라 상시 자유라는 뜻.

**처방**: 노드마다 roll/pitch만 구속하는 중력 prior(**yaw는 자유**), σ는 실측
VINS tilt 잔차에서 도출. Rayleigh 분포 가정으로 σ = median/1.1774 →
0.741/0.703/0.516° → pooled **0.65° (0.0114 rad)**.

이는 튜닝이 아니라 프론트엔드가 실제 관측한 양을 그래프에 넣는 것이다. yaw를 자유로
두는 것이 설계의 핵심 — yaw까지 묶으면 VINS의 yaw 드리프트를 참으로 고정해버린다.

### 5.7 Σ의 판별력 (중요한 음성 결과)

tr(Σ)가 실제 오차를 순서대로 맞히는지 십분위로 측정:

| tr(Σ) 십분위 | 1 (최저) | 3 | 5 | 7 | 9 | 10 (최고) |
|---|---|---|---|---|---|---|
| 평균 실제 오차 | 0.074 | 0.055 | 0.048 | 0.055 | 0.084 | 0.093 |

**U자형이다.** 가장 확신하는 십분위(0.074 m)가 가장 불확실한 십분위(0.093 m)와 거의
같게 나쁘다. Spearman은 로봇별로 부호가 갈린다(−0.112 / +0.284 / +0.365, pooled +0.155).

**즉 앵커 조건에서는 어떤 α를 골라도 포즈 항이 물리적 의미를 갖지 못한다.** 가중을
걸면 최상위 십분위를 깎는 동시에 거의 똑같이 나쁜 최하위 십분위를 올려준다.
원인은 과신(1.8×에 불과, α가 흡수)이 아니라 **판별력 부재**다.

이후 yaw 층화로 숨은 양의 상관이 일부 발견되어, U자형의 일부는 인공물이었다.
그러나 결론(앵커 조건에서 포즈 항은 무동작)은 유지된다.

**α 결정**: **0.3 유지**. 앵커 조건에서 trΣ 0.0010~0.0026 → w 0.991~0.997로 포즈 항이
**무해하게 잠자는** 것이 올바른 동작이다. 판별 정보가 없는 상황에서 α를 낮춰 항을
깨우면 반정보적 가중을 주입하게 된다. 한편 §4.9의 anchor-free 조건에서는 trΣ가
0.1~1.0 m²로 커져 α=0.3이 강하게 판별한다 — 즉 0.3은 "판별 정보가 있을 때만 작동하는"
범위에 이미 맞춰져 있다.

## 6. Phase 1/3 — 불확실성 인지 Occupancy 파이프라인

### 6.1 설계 (계획서 §4)

**가중 log-odds**:

```
l(c) ← clamp( l(c) + w · l_meas )
w = exp(−tr(Σ_pos)/α) · exp(−σ_Z²/β)
```

**안전 비대칭**: |l_free| = 0.40 < |l_occ| = 0.85.
근거: 항법에서 "벽인데 free로 오판(false-free)"이 "통로인데 occupied로 판정"보다 훨씬
위험하다.

**unknown ≠ free**: 미관측과 관측된 자유공간의 혼동은 사람 진입 안내에서 치명적.

### 6.2 확정 파라미터

| 항목 | 값 | 근거 |
|---|---|---|
| resolution | 0.10 m | — |
| l_occ / l_free | +0.85 / −0.40 | 안전 비대칭 |
| clamp | [−2.0, +3.5] | — |
| **tau_occ** | **= l_occ** | 단발 관측 기여가 w·l_occ ≤ l_occ이므로 이 값이면 관측 1회로 occupied가 **원리적으로 불가능**. 성질을 만족하는 최소값이라 임의성 없음. 탈락 셀은 free가 아니라 unknown이 되어 안전 등가. |
| α | 0.3 m² | §5.7 |
| β | 0.5 | — |
| max_ray | 5.0 m | 스테레오 신뢰 한계 |
| f·B | 21.7 | σ_Z = Z²/(f·B) |

**σ_Z 스케일**: 1 m → 0.05 m, 3 m → 0.42 m, 5 m → **1.17 m (12 voxel)**.
w_depth는 근거리 0.99, median(σ_Z=0.67) 0.41, 원거리 **0.065** — 15배 분산.

### 6.3 발견·수정된 버그 4건

모두 측정으로 원인을 특정한 뒤 수정했다.

**(1) free 증거 중복 계산 + 대각선 셀 누락**
호길이 `res/2` 등간격 샘플링이 한 voxel에 2~4회 누적(축 2배, 대각 최대 4배)하고,
동시에 광선이 모서리를 스치는 voxel은 **통째로 건너뛰었다**(대각선에서 18/53셀만 방문).
유효 l_free가 −0.8~−1.6이 되어 **안전 비대칭이 코드에서 역전**돼 있었다.
→ 정확한 벡터화 DDA(`_dda_batch`)로 교체. 사물 voxel +24%(fused) / +30%(GT),
0.37 s/frame 유지.

**(2) `tau_occ = 0`**
log-odds > 0이면 occupied이므로 종단 voxel은 1회 관측(+0.85·w)만으로 occupied가 됐다.
스테레오 오정합 픽셀 1개가 영구 큐브가 되는 구조.
→ `tau_occ = l_occ`. 부유큐브 2,393→1,242(fused), 225→98(GT).

**(3) `write_bt` 파괴적 호출**
OctoMap `writeBinary`가 내부적으로 max-likelihood 변환 + pruning을 수행해 트리를
변경하는데, 드라이버가 이를 시각화·분류보다 **먼저** 호출했다. 지금까지 보고된 free
카운트가 "병합 후 leaf 개수"였다(172,802 → 실제 495,241).
→ 분류/플롯 후 마지막에 쓰기.

**(4) 동료 마스킹 프레임**
3대가 동시 비행하며 서로를 관측해 공중에 궤적 형태 큐브를 남긴다. 마스킹 중심이
카메라였던 것을 기체 중심(`p_body`)으로 수정(0.11 m = `dyn_radius`의 31%).
GT에서 98→35, fused에서는 변화 없음 — 당시 fused 회전 오차가 종단점을 다른 곳으로
보냈기 때문(포즈 오차의 심각성을 보여주는 부수 증거).

**회귀 테스트**: `tests/test_ray_traversal.py` 6개. 셀별 log-odds **값**을 참조 DDA와
대조한다. 기존 체크가 voxel **개수**만 봐서 (1)을 통과시켰기 때문이다.

## 7. §4.9 — 협업 이득의 인과 규명

### 7.1 조건 설계 (anchor-free)

계획서는 세 군데서 anchor-free를 명시한다: §1 제약("사전 인프라 설치 불가능한 재난

있었음 — 정정).

**커버리지 교란 분리 (A1)**: 지도를 **항상 ifo001 카메라만으로** 생성하고 포즈만
조건별로 교체했다. A→B→C에서 inter 제약 수와 시점 커버리지가 동시에 변하는데, §4.9의
주장은 Σ 경로에 관한 것이므로 후자를 고정해야 인과 주장이 성립한다.

### 7.2 결과

| 조건 | C(N,2) | ATE_per | tr(Σ) med | w_pose med | w span | IoU@1vox | false-free |
|---|---|---|---|---|---|---|---|
| A | 0 | 0.2124 | 0.940 | 0.066 | 1.000 | 0.306 | 5.978% |
| B | 1 | 0.1876 | 0.130 | 0.544 | 0.996 | 0.537 | 4.999% |
| C | 3 | 0.2248 | 0.074 | 0.810 | 0.424 | 0.518 | 5.268% |
| D | 3+앵커 | 0.0748 | 0.0015 | 0.995 | 0.005 | 0.584 | 4.426% |
| E | 앵커만 | 0.0892 | 0.0021 | 0.993 | 0.008 | 0.552 | 4.865% |
| GT | — | 0 | — | 1.0 | — | 1.0 | 0 |

**고리 ①②③ 성립**:
- **Σ↓**: C(N,2) 0→1→3에서 tr(Σ) 0.940 → 0.130 → 0.074 m² (**13배 감소**)
- **w↑**: 0.066 → 0.544 → 0.810
- **품질↑**: IoU@1vox 0.306 → 0.537, false-free 5.978% → 4.999%

**계획서가 명시한 검증**: ρ(trΣ, false-free) = **+0.900**, Pearson(log trΣ, ff) = +0.886,
ρ(trΣ, IoU) = **−0.900** (5조건, trΣ 3자릿수 범위)

**anchor-free 전환 판단이 데이터로 정당화됐다**: w span이 앵커 조건에서 0.005로 죽어
있고 anchor-free에서 1.000/0.996/0.424로 살아난다. 포즈 항이 앵커 때문에 잠자고 있었다는
진단이 맞았다.

**커버리지 이득 (별도 측정)**: 1대 39,427 → 3대 64,225 occupied (**+63%**).

### 7.3 정합 오차 — 묻혀 있던 긍정 결과

| 조건 | 정합 격차 (공동 정렬 − 로봇별 정렬) |
|---|---|
| C (anchor-free 3쌍) | 0.0088 m |
| D (3쌍 + 앵커) | 0.0074 m |
| E (앵커만) | 0.0116 m |

**드론 간 레인지만으로 앵커 6개와 동등한 정합을 달성**했고, 앵커만 쓰는 것보다는
오히려 낫다. 계획서의 anchor-free 전제를 직접 지지한다.

ATE와 갈리는 것이 의미 있다 — anchor-free는 ATE가 3배 나쁘지만(0.225 vs 0.075)
IoU는 11%만 나쁘다(0.518 vs 0.584). **앵커는 절대 위치를, inter는 상대 정합을 준다**는
역할 분담이 숫자로 드러났고, 합동 지도에서 중요한 것은 후자다(전체가 통째로 밀리는
것은 지도를 뭉개지 않지만 로봇끼리 어긋나면 벽이 번진다).

계획서 §2.2("UWB는 정합, VIO는 매핑")가 측정으로 확인된 것이기도 하다 — ATE는
비단조(0.212/0.188/0.225)인데 Σ와 정합은 단조 개선한다. inter range는 정합을 개선하고
Σ를 줄이지 자기 궤적 형상을 개선하지 않는다.

### 7.4 한계

1. **첫 쌍 이후 포화**: A→B는 결정적(IoU 0.306→0.537)이지만 B→C는 평평하거나 약간
   나빠진다. 단일 로봇 자기 지도에는 2·3번째 쌍이 기여하지 않는다.
   (ρ=+0.900의 유일한 순위 역전이 이 B·C 뒤바뀜이다.)
2. **정합 격차 지표가 게이지 prior 개수에 교란됨**: 조건 A의 격차가 0.0000인데, A는
   성분 3개라 게이지 prior가 3개이고 모두 mocap 초기값에서 시드되어 이미 세 로봇이
   mocap 프레임에 있다. **{C,D,E} 안에서만 비교 가능**하다. 앵커 기반 초기화가 이를 푼다.
3. **anchor-free는 ATE에서 ~3배 손해** (0.19~0.22 vs 0.075 m). 예측대로이고 계획서가
   상정한 조건이다.
4. **조건 A의 낮은 IoU는 "틀렸다"가 아니라 "매핑을 거절했다"**: w≈0.066이 증거를
   억제해 voxel이 21,655개(GT 38,523)뿐이다. IoU는 부재를 벌점으로 계산하므로 성김과
   오류가 섞인다. A 조건에서는 false-free rate가 더 정직한 지표다.

## 8. 음성 결과 — 포즈 불확실성 가중의 실패

계획서 사슬의 **고리 ④(w↑ ⇒ 품질↑)** 가 포즈 항에 대해서는 성립하지 않는다.
두 가지 인코딩을 각각 사전등록 검정으로 시험했고 둘 다 실패했다.

### 8.1 검정 1 — 스케일링 (3-arm 매개 검정)

w = w_pose × w_depth이므로 통째로 끄면 깊이 항 효과까지 꺼진다. 포즈 항만 분리하기 위해
3개 arm을 구성했다: ① full, ② depth-only(w_pose ≡ 1), ③ uniform.

**(arm1 − arm2) = 포즈 항의 기여.** D·E는 w span 0.005이므로 내장 음성 대조군이다.

| 조건 | w span | full ff | depth-only ff | Δff | Δprec | Δrecall |
|---|---|---|---|---|---|---|
| A | 1.000 | 5.978% | 5.875% | **+0.103 pp** | +0.013 | **−0.145** |
| B | 0.996 | 4.999% | 4.890% | **+0.109 pp** | +0.036 | −0.042 |
| C | 0.424 | 5.268% | 5.214% | **+0.054 pp** | +0.020 | −0.024 |
| D·E | 0.005 | — | — | ≈ 0 | — | — |

반증 조건 미발동(D·E ≈ 0)이므로 부호를 신뢰할 수 있다. **크기 순서는 예측대로 w span을
따르지만(A>B>C≫D·E) 부호가 전부 양수 — 포즈 항이 false-free를 늘린다.**

**메커니즘**: w_pose는 프레임 단위 스칼라이므로 l_occ = +0.85와 l_free = −0.40을
**같은 비율로** 줄인다. 어떤 셀이 가중치 낮은 프레임에서 occupied 증거를, 가중치 높은
프레임에서 free 증거를 받으면 더 큰 occupied 항이 상대적으로 더 억제되어 셀이 free로
넘어간다. **안전 비대칭이 가중치 비율에 무력화된다.** A의 recall −0.145(occupied 19k
소실)가 같은 현상의 반대편이다.

**결정적 대조**: uniform arm(가중 전혀 없음)에서도 A→B가 개선된다
(ff 5.791% → 4.821%, precision 0.239 → 0.293). 즉 **A→B→C 지도 개선은 포즈가 좋아져서지
가중 때문이 아니다.**

**비용 비교**: 깊이 항은 precision +0.070~0.134를 recall −0.053~−0.074로 사는데,
포즈 항은 +0.013~0.036을 −0.024~−0.145로 산다 — 훨씬 나쁜 거래다.

### 8.2 셀 단위 상관 (n=5 → ~310,000)

uniform arm에서 측정했다(그곳에서는 trΣ가 지도를 만들지 않으므로 순환논증 없음).

| 조건 | n | Spearman ρ | 상위 5개 십분위 false-free | 상대위험 |
|---|---|---|---|---|
| A | 310,251 | +0.0474 | 5.03 → 6.29 → 7.11 → 7.63 → **8.19%** | **1.6×** |
| C | 307,691 | +0.0183 | 3.29 → 4.26 → 5.59 → 5.92 → **7.78%** | **2.4×** |
| D | 305,282 | −0.0136 | 무패턴 (trΣ 폭 0.00098~0.00235뿐) | — |

**ρ 해석 주의**: false-free는 기저율 5%의 이진 변수다. 연속변수 vs 5% 이진변수의
Spearman은 완벽히 분리돼도 동점 랭크 때문에 **~0.47이 상한**이다. 즉 0.047은 "0에
가까움"이 아니라 **이론 최대의 약 10%**다. 효과 크기는 십분위 상대위험(1.6~2.4배)으로
읽어야 하며, 이는 실재하고 중간 정도인 효과다. **문서·논문에는 ρ가 아니라 십분위 표를
주 지표로 쓸 것.**

A의 trΣ는 체인을 따라 자라 관측 시각·장소와 상관된다는 교란이 있으나, C는 trΣ가
range 기하로 결정돼 시간 의존이 약한데도 같은 단조 상승을 보여 이 교란을 부분적으로
해소한다.

**즉 tr(Σ)는 실재하지만 약한 예측자이고, 상위 구간에서만 유효하다.**

### 8.3 검정 2 — 공간 분산 (사전등록, 실패)

**원리**: 포즈 불확실성은 **위치 불확실성**("장애물이 있는데 어디인지 모른다")인데
log-odds 스케일링은 **존재 불확실성**("있는지 자체가 의심스럽다")을 표현한다.
서로 다른 진술이므로 전자를 후자로 인코딩하는 것은 범주 오류다.
올바른 처리는 증거를 약하게 만드는 것이 아니라 **√trΣ 범위에 퍼뜨리는 것**이다.

자유 파라미터를 없애기 위해 분산 폭에 임의 계수를 붙이지 않고 σ = √(trΣ_pos)를
그대로 사용, 질량 보존(재배치만, 약화 없음), w_pose는 끔.

| 조건 | √trΣ | 분산 폭 | Δff | Δprec | Δrecall |
|---|---|---|---|---|---|
| A | 0.969 m | **19.4 vox** | −5.369 pp | −0.207 | +0.602 |
| B | 0.361 m | 7.2 vox | −4.320 pp | −0.203 | +0.494 |
| C | 0.273 m | 5.5 vox | −4.555 pp | −0.148 | +0.496 |
| D | 0.039 m | 0.8 vox | **−1.632 pp** | −0.050 | +0.164 |
| E | 0.044 m | 0.9 vox | **−1.920 pp** | −0.039 | +0.186 |

**반증 조건 P2 발동** — D·E가 ≈0이어야 하는데 −1.6/−1.9 pp 움직였다. 등록한 규칙대로
분산에 대한 주장을 하지 않는다.

원인: 등록 규칙이 occupied 분산에는 sub-voxel 가드를 걸었으나 **free 절단에는 걸지
않았다**. D의 σ = 0.0386 m → 절단 0.77 voxel이고, 지도를 만들지 않는 계수 진단으로
프레임당 free 증거의 2.3%(D)·2.6%(E)가 사라졌다 — 하필 종단 직전, free/occupied 경계
셀들이다. 규칙의 두 절반이 1 voxel 아래에서 불일치해 D·E가 애초에 no-op이 아니었다.
(예측이 데이터에 대해 틀린 것이 아니라 등록한 규칙의 동작에 대해 틀렸다.)

**명목상 개선도 퇴화다** — 사전등록한 보조 지표가 잡아냈다:

| 조건 | 분산 arm occupied | GT(38,523) 대비 | precision |
|---|---|---|---|
| A | 352,912 | **9.2배** | 0.308 → **0.101** |
| B | 181,705 | 4.7배 | 0.396 → 0.193 |
| C | 155,234 | 4.0배 | 0.369 → 0.222 |

free 셀이 314,975 → **110,814**로 붕괴해서 ff%가 떨어진 것뿐이다 — "전부 occupied로
선언"하는 자명한 해. 안전하지만 쓸모없다.

**판정: 불성립. 세 번째 변형 없음.** 두 독립 근거(음성 대조군 반증 + 퇴화)로 판정했고,
등록한 1회 검정 규칙대로 변형을 시도하지 않았다.

### 8.4 종합 메커니즘 서술

> 위치 불확실성을 **존재 불확실성으로 인코딩(스케일링)** 하면 안전 비대칭이
> 무력화된다. **공간 분산으로 인코딩** 해도 — 등록한 형태로는 — 복구되지 않는다.
> 비대칭을 무력화하는 것이 아니라 지도를 압도한다: 경계의 free 증거를 지우고
> occupied를 5~19 voxel에 퍼뜨려 거의 전부가 occupied가 된다.

**범주 오류 진단 자체가 반증된 것은 아니다.** 실패한 것은 이 인코딩이다 — √trΣ를
계수 없이 쓰면 anchor-free에서 5~19 voxel이라 0.10 m 격자에 너무 거칠고, 같은 폭으로
free를 절단하면 지도가 의존하는 경계 증거가 사라진다.

**더 깊은 발견 — 작동 영역(regime) 문제**:

| 조건 | √trΣ | voxel 환산 (0.10 m 격자) |
|---|---|---|
| A | 0.969 m | **9.7 voxel** |
| B | 0.361 m | 3.6 |
| C | 0.273 m | 2.7 |
| D | 0.039 m | 0.4 |
| E | 0.044 m | 0.4 |

**포즈 불확실성이 격자보다 크면 그 해상도의 지도는 원리적으로 정의되지 않는다.**
카메라가 1 m 오차로 어디 있는지 모르는데 10 cm 격자 지도를 만들 수는 없다. 이때
불확실성을 정직하게 처리하는 방법은 억제(→성긴 지도)와 번짐(→전부 occupied) 둘뿐이고
둘 다 쓸모없다. 정보가 없는 것을 기법으로 만들어낼 수 없다.

그리고 근본적 긴장이 드러난다:
- 포즈 불확실성이 **의미 있게 변하는** 조건(anchor-free)에서는 크기가 격자를 2.7~9.7배
  넘어서 가중이 무의미
- 불확실성이 **격자보다 작은** 조건(앵커)에서는 균일해서(span 0.005) 가중할 것이 없음

즉 "포즈 불확실성으로 가중한다"가 작동할 창이 이 데이터에는 존재하지 않는다.
구현 문제가 아니라 작동 영역 문제이며, 스케일링·분산 둘의 실패를 하나로 설명한다.

### 8.5 왜 깊이 항은 작동하는가

σ_Z도 원래 위치 불확실성이지만 **우연히 존재 불확실성과 상관돼 있다** — σ_Z가 크다는
것은 곧 원거리라는 뜻이고, 원거리 스테레오는 실제로 **존재하지 않는 유령 점**을 만든다.
그래서 존재 불확실성으로 인코딩하는 것이 맞아떨어진다. 포즈 오차는 관측이 전부 실재하고
위치만 틀리므로 그 인코딩이 틀린 것이다.

**서술 가능한 결론**:

> 불확실성 인지 매핑은 불확실성이 **존재 불확실성과 상관될 때(깊이)** 작동하고,
> **순수 위치 불확실성일 때(포즈)** 작동하지 않는다. 그 경계와 이유를 규명했다.

## 9. 방법론적 결과

개별 실험과 별개로 확립된 것들.

1. **false-free rate는 게임 가능한 지표다.** 전부 occupied로 선언하면 0에 가까워진다.
   계획서 §4.9가 이를 주 지표로 명시했으나, **free 셀 수와 precision/recall을 반드시
   함께 보고**해야 한다. §8.3에서 이 지표만 봤다면 실패를 성공으로 오독했을 것이다.
2. **회귀 테스트는 개수가 아니라 값을 비교해야 한다.** voxel 개수만 보는 테스트가
   free 중복 계산 버그를 통과시켰다.
3. **이진 결과에 대한 상관계수는 기저율에 눌린다.** 5% 이진변수와의 Spearman 상한은
   ~0.47. 효과 크기는 십분위 상대위험으로 보고할 것.
4. **기준선의 유한 정확도를 인정해야 한다.** GT 잔여 오프셋이 판정 문턱을 감싸면
   단일 문턱을 고르지 말고 스윕 곡선 전체를 보고한다.
5. **사전등록이 결과를 구했다.** §8.3에서 사전 기록한 보조 지표와 음성 대조군이 없었다면
   퇴화를 개선으로 보고했을 것이다.
6. **음성 대조군을 설계에 내장할 것.** D·E(w span 0.005)가 §8.1의 부호를 신뢰할 수 있게
   만들었고, §8.3의 구현 결함을 잡아냈다.

## 10. 알려진 한계

### 데이터·환경
- **occupancy GT 없음** — MILUV는 점유지도 정답을 제공하지 않는다. IoU·false-free의
  절대 정량 평가는 시뮬레이터가 필요하다(계획서 §8 이원 전략).
- **`obstacles_1_random3_0b`는 ifo001 bag만 존재** — 이 시퀀스로 3대 협업 실험 불가.
- **앵커 6개가 모두 ~1.7 m 높이** — 수직(VDOP) 관측 불가.
- **스테레오 기선 5 cm, f·B = 21.7** — 3 m에서 σ_Z 0.42 m, 5 m에서 1.17 m.
  원거리 사물 매핑은 하드웨어 한계.
- **`default` 시퀀스는 `obstacles_bool = false`** — 사물이 AprilTag 기둥 13개·삼각대
  뿐이고 전부 방 가장자리(궤적에서 0.6~3.8 m). 사물 매핑 시연에 약한 시퀀스.

### 기준선
- **레버암 미식별** — GT 기준선에 0.05~0.17 m 규모 잔여 body-origin 불확실성.
  AprilTag PnP가 필요하다.
- **셀 단위 판정 불가** — 위 잔여 오프셋이 50% 교차점(1.24 voxel)을 감싼다.

### 추정
- **Σ 1.8× 과신** — 단일 원인 없음. 허용 범위로 두고 진행.
- **yaw 드리프트 잔존** — 중력은 yaw에 정보가 없다. 융합이 부분 개선
  (ifo003 −4.48 → +0.17 °/min, 26배 평탄화; yaw 오차 76% 감소). 드리프트가 실재했던
  로봇에서만 개선되고 나머지는 애초에 평탄해 개선 여지가 없었다 — 결함이 있던 곳에만
  나타나는 개선이라 인과 주장으로는 오히려 방어하기 좋은 형태.
- **정합 격차 지표가 게이지 prior 개수에 교란** — {C,D,E}에서만 비교 가능.

### 계획서와의 편차 (문서화됨)
- 초기 프레임 정렬이 mocap Umeyama (계획서·CoVOR는 마커 기반). 초기값에만 사용.
- 현행 앵커 사용은 CoVOR 재현 잔재. 주 실험은 anchor-free로 복귀 완료.

## 11. 남은 작업

### 우선순위 높음
1. **Phase 4 — 사람 진입 변환** (미착수). 2D 슬라이스 + erosion으로 통과 가능 폭 판정.

### 우선순위 중간
3. **종류별 bias 분리** — 앵커 +0.087 vs inter +0.004. 융합 오차의 바닥을 이 bias가
   정하므로 실질적 정확도 개선 여지가 있다(`bias_mode` 활용).
4. **레버암 AprilTag PnP** — GT 기준선을 선명하게. §4.9 궤적 지표에는 영향 없음
   (상수 오프셋은 정렬에서 흡수).
5. **결과 문서·그림 정리** — 이 문서를 논문 구조로 재편.

### 사후 가설 (시도 시 새 사전등록 필요)
6. **격자 해상도를 불확실성에 맞추기** — 조건 C의 √trΣ = 0.27 m에 맞춰 0.3 m 격자로
   가면 분산 폭이 ~1 voxel이 되어 작동할 가능성이 있다.
   ⚠ **이 아이디어는 §8.3 결과를 본 뒤에 도출됐다.** 지금 시도하면 forking paths다.
   진행하려면 새 사전등록 + "사후 도출된 가설"임을 명시해야 한다.

### 하지 않을 것
- 포즈 가중의 **세 번째 변형** — §8.3 판정 규칙에 따라 종료.
- `random` 시퀀스로 교체 — 검토 완료. 드리프트가 안 쌓이는 이유는 궤적 모양이 아니라
  방 크기(좁은 실내 재관측)다.

## 부록 A — 함정 목록 (재발 방지)

1. **ORB-SLAM3 `loopClosing: 0`은 map merging까지 끈다** (`mbActiveLC` 단일 플래그).
   드론 영상에서 궤적이 4~15%로 파편화.
2. **Vicon 정렬 궤적을 fusion 입력으로 쓰면 안 된다.** `_vio_loop_aligned_and_shifted.csv`
   계열은 GT로 이미 정렬돼 있어 UWB의 역할을 GT가 대신한다. **에러 없이 조용히 실패하고
   오히려 결과가 좋아 보이므로 특히 위험.** fusion 입력은 raw local-frame `vio.csv`.
3. **Σ는 VINS가 아니라 GTSAM 융합에서 나온다** (계획서 §2.5, marginal covariance H⁻¹).
   VINS 출력에 공분산이 없는 것은 정상.
4. **광선 free 증거 중복/누락** — 회귀 테스트는 개수가 아니라 셀별 log-odds **값**을 비교.
5. **OctoMap `write_bt`는 파괴적** — 분류·플롯을 먼저, 쓰기를 마지막에.
6. **`tau_occ = l_occ`의 근거** — 관측 1회로 occupied가 원리적으로 불가능해지는 최소값.
   임의로 낮추지 말 것.
7. **UWB CSV의 std 컬럼은 낙관적** (평균 0.17 vs 실제 0.22).
8. **`timeshift_ns` 누락** — MILUV 규약은 `timeshift_s + timeshift_ns/1e9`.
   `range_tol = 0.05 s`이므로 0.256 s 오프셋은 UWB 연관을 전량 실패시킨다.
9. **VINS는 body 포즈, occupancy는 camera 포즈** — `body_T_cam0` 회전이 거의 90°.
10. **raw mocap에 173~180° 회전 점프** — MILUV 로더(spline + 이상치 제거)를 쓸 것.
11. **`pkill`/`pgrep` self-매칭** — `pgrep -f 'rosbag play'`가 자기 셸을 매칭해 exit 144.
    실제 고아 프로세스가 아니다.
12. **`obstacles_1_random3_0b`는 ifo001 bag만 존재.**
13. **`--drones`는 출력만 필터링했다** — 그래프 수준 ablation은 `inter_pairs` /
    `anchor_robots`를 써야 한다.
14. **SE(3) 전환 시 중력 관측이 버려진다** — `BetweenFactorPose3`는 상대 회전만 담으므로
    노드별 중력 prior가 필요하다(물리는 맞지만 코드가 인코딩하지 않았던 사례).
15. **VINS 산출물은 저장소 밖** (`ws/vins_ws/`), git 미추적 — 유실 주의.
