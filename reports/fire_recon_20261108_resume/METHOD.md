# 소방관 수색 구역 도착을 위한 공통 탐색 파이프라인 비교

질문은 제한된 정찰 시간에 **유효한 사람 진입 경로와 실제 차단을 확인하는 데 현재 entry 관측 가치가 unknown보다 도움이 되는가**다. 여기서 수색 구역은 도착 목표 영역이다. 방 전체의 수색 완료나 화재에서의 안전한 작업을 뜻하지 않는다.

## 실제 입력과 장면 버전

실제 확인한 입력은 앞서 사용자가 승인한 확대 화재 10개 건물의 `web/fire_buildings_3d.html`, `results/fire_buildings_large_fire_20261107/*/{scene.glb,scene.ply,collision_geometry.json,scene.json,gt_voxel.npz}`다. 같은 viewer의 확대본은 `web/fire_buildings_large_fire_3d.html`과 바이트가 같다. 요청 이름 `fire_buildings_3d(1).htm`은 발견되지 않아 동일성 확인 질문을 남겼다. 이번 메시지는 §2의 공통 후보 생성/수 제한까지 수신했다. 이후 조건이 전달됐다고 가정하지 않고, 우선 기존 승인 자료와 최신 공통 설정을 유지한다.

원본은 보존했다. 원래 3층 건물의 2층 계단 시작점에 27cm 바닥 누락이 있어, 별도 복사본에 하부 층계참만 10개 추가했다. `ReconFireWorld`를 opt-in으로 사용한다. 10개 모두 원래 부품/화재가 같고 실제 보관 PLY의 고체 꼭짓점/삼각형과 일치함을 확인했다. 보완 자산은 `results/fire_recon_20261107/assets/`에 있다. 장면 생성 seed는 71100–71109, 설정의 scene_seeds 0–9는 건물 인덱스다.

완전한 메시의 지지/몸체 연결로 독립 정답을 만들었다. 목표 218개 중 **도달 가능 141, 차단 77**이며 3층 도달 가능한 목표가 **29개**다. 완전 관측 공통 판정기는 유효 경로 141/141, 올바른 차단 71/77, 무효/차단 오판 0이었다. 6개 차단은 완전 관측에서도 보수적 증명 부족으로 미확인이다. 이 검증은 드론이 실제 제한 시간에 얻은 성능과 구분한다.

입구/목표는 기존 최신 FireWorld의 영역 정의를 그대로 쓴다. 입구는 실제 개구부 안 폭 1.2m, 목표는 각 방 바닥 내부(경계 5cm 제외)이며 층 범위 −0.10~+0.25m다. 좌표 스냅은 없다. 입구와 목표가 겹치면 한 점 경로도 현재 정의에서 유효할 수 있어 경로 길이·1m 초과 여부를 보조 표로 공개한다. 결과를 보고 목표를 이동/제외하지 않는다.

## 고정 예산과 단일 비교 요소

[설정](../../configs/fire_recon_20261107.json): 10개 건물 × 실행 seed0 × clean/strong × unknown/entry = **40개 조건**. 드론 4대, 임무 180초, 시작 0/2/4/6초, 실행 tick/촬영 0.25초(4Hz), 평가 8초 및 마지막, 배정 4초, 지도 저장 20초다. 후발 입구 대기도 임무 시간에 포함한다. 위치 perfect_odometry, 즉시 공유 지도, 운동학적 궤적 정확 추종이다. 실시간 수행을 주장하지 않는다.

두 정책은 같은 후보 생성·수 제한·짐벌·중앙 배정·A*·FUEL 시간화·예약/충돌·센서·지도·사람 판정을 쓴다. 이후 지도가 달라져도 후보 생성 절차와 계산 예산은 같다. 최대 후보 24(관측 FREE의 frontier와 약한 표면 재관측), 구간 영향 검사 최대 6, 가시성 표본 최대 24, 활성 예약 최대 4다. 높이는 현재 관측 FREE에서 샘플하며 참 층/문/방 목록으로 후보를 만들지 않는다.

unknown은 후보가 줄일 것으로 예상되는 미관측 복셀의 추가 이득이다. entry는 미확인 구간만 열림/닫힘으로 바꿨을 때 달라지는 목표 집합과 발판/몸 공간 가시성의 최솟값을 쓴다. 같은 목표/표면 중복을 제한하고 필요한 추가 지지 증거를 반영한다. 현재 entry 수식/가중(0.8/0.2), unknown 정규화 1500, 시간 비용 0.008은 수정하지 않았다. 양의 값이 없을 때 공통 unknown 규칙으로 돌아가며 시간/선택을 기록한다. 구간 중요도가 단일 관측으로 경로 완성을 보장하는 값은 아니다.

최종 이동 비용은 계획된 경로·속도/가속도·yaw·예약 대기·촬영 시간에서 계산한다. 기체 반경 0.14m+여유 0.04m, 1m/s, 1.5m/s², yaw90°/s, pitch60°/s, 예약0.1초, 최대 대기8초를 유지한다. FUEL 원본 Polynomial을 호출하는 standalone 어댑터이며 RACER/FUEL 전체 ROS 재현이 아니다. [외부 코드 커밋/빌드 감사](../closed_loop_20261105/EXTERNAL_AUDIT.md)를 계승한다.

## 센서와 정보 분리

RealSense D455급 공개 사양을 참고한 **낙관적 깊이 관측 모델과 통제된 관측 저하 조건**을 유지한다. optical Z 0.6–6m, FOV87°×58°, baseline0.095m, 320×180 깊이 출력 샘플이다. 명목 센서 해상도/FPS와 시뮬레이션 격자/적분 속도는 [SENSOR_MODEL](../depth_model_20261106/SENSOR_MODEL.md)에서 구분한다. 양안 영상을 생성하거나 SGBM을 실행하지 않는다.

실제 카메라 포즈/짐벌에서 첫 표면을 raycasting하고 오른쪽 카메라 가시성·동료 가림을 유지한다. 정상 σ=0.002+0.001Z² m, 기체 편향1mm, 정상 누락0.5%/이상치0.05%, 공간0.15m·시간0.75s 상관과 독립 성분이다. 범위 밖 오염 깊이는 invalid이며 free ray를 만들지 않는다. 기존 모형의 모든 수치를 유지한다.

75개 화재 소스와 고체 마스크를 가진 무차원 공통 확산장을 사용한다. strong은 k3/a0.20/q0.005, clean은 k=a=q=0이며 정상 센서 오차는 남는다. τ와 T는 시뮬레이터 내부에서 오차·누락·이상치만 만든다. 실제 화재 농도·열·CFD 모델이 아니다. 참 깊이·오차·법선·이상치 마스크·T는 정책에 전달하지 않는다. 공개 입력은 오염 Z/sigma/valid와 카메라 포즈·시각·동료 위치다.

정책은 현재 관측 지도, 현재 추정 상태, 공통 건물 외곽·입구·익명 목표 구역·대기 공간만 쓴다. 참 메시/도달 정답/화재 좌표는 센서 생성·실제 충돌 결과·평가 쪽에 둔다. 실제 포즈로 관측하고 추정 포즈로 적분한다(이번에는 같음). 미래 전체 궤적의 최적화 포즈를 쓰지 않는다.

## 사람 모델과 실제 제시 경로

서기/숙이기/기기 높이1.90/1.40/0.90m, 폭0.70/0.45m, 최대 걸음 높이0.18m, 발 offset0.025m, 대각선 제한을 유지한다. 발판은 서로 다른 촬영 2회·evidence≥1.2·높이 std≤0.05m다. 확인 그래프에 미관측 발판 0.5m 틈 규칙을 넣지 않는다. 실제 관측 XY/표면 평균 Z/산포/점유 endpoint 최대 높이를 사용하는 최신 공통 표현을 유지하며 참 바닥으로 보정하지 않는다.

통과 가능은 확인 그래프의 실제 경로, 미확인은 증거 부족, 차단은 관측된 폐쇄 근거가 있고 미확인 연결을 완화해도 대안이 없을 때다. 경로 부재만으로 차단하지 않는다. 경로를 기준 메시에서 시작/목표/층·지지·걸음·자세 변화·점 사이 몸체 sweep으로 검증한다. 목표에 우회로가 있어도 제시 경로가 막힌 문을 지나면 무효다. 평가기가 참 지도에서 더 좋은 경로로 대체하지 않는다.

기준의 도달 불가는 10cm 지지 로드맵에 대한 정답이며 모든 연속 공간 우회가 없다는 수학적 증명은 아니다. 기준 라벨과 독립 검증 경로의 모순을 별도 감사한다. 예전 traverse.py 면적 지표/기본 동작은 보존하며, 복층을 겹친 XY 면적을 새 목표 지표로 읽지 않는다.

## 실행 재사용과 재현

2층 건물 5개는 형상 변화가 없으므로 기존 동일 조건의 20회를 재사용한다. 핵심 코드/센서·사람·이동·시간 설정/실제 PLY/사전 구역의 일치, 대표 first/middle/last 깊이 재생을 확인한 뒤 포함한다. 충돌/실패도 그대로 남긴다. 3층 건물의 20회는 새로 실행한다. 재사용을 새 독립 반복 실험으로 세지 않는다.

시작 상태·사용자 stage/unstaged patch·자산/소스 해시는 intake에, gate/본 실행 소스와 설정은 각 source_snapshot/manifest에 보존한다. 재사용 메타데이터는 복사하고 큰 깊이/지도는 읽기 참조 링크로 둔다. 각 실행의 config/prior/reference_targets, 실제/추정 궤적, frames NPZ/CSV, map_version, 후보/배정/선택, 이벤트, 지도, 실제 경로와 검사 이유를 저장한다. [재실행](REPRODUCE.md), [실제 작은 검증](PREFLIGHT.md), [자료 인수](INTAKE.md)를 참조한다.
