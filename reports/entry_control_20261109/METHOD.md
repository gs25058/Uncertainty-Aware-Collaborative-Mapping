# 관측 가치와 드론 제어를 분리한 추가 실험

> 2026-11-09 23:07 사용자 요청으로 이미 시작한72회 배치와 재생 진단까지만 마친다. 결합24회와 새 시드 검증80회는 미실행이다. 아래에 보존한96/80회는 이전 계획이며 완료 수가 아니다. [현재 범위의 실제 결과](../entry_optimization_20261109/current/RESULTS.md)에서 순수 목적함수와 조종 조건을 구분해 보고한다.

사용자가 목적함수의 큰 변경과 새 조종 방식을 허용함에 따라 시작했다. 기존 순수 목적함수 실험128회와 새 시드100회는 동결 소스로 계속한다. 여기 결과를 그 실험의 목적함수만 바꾼 효과로 합산하지 않는다.

4대·180초·4Hz·동일 깊이 오류/연기장·동일 목표·인체·경로 평가기를 쓴다. 정답은 기하학적 통과 가능성이다. 참 형상은 센서와 평가에만 남는다. 후보 생성과24개 제한, 중앙 배정·동료 예약, 속도1m/s·가속도1.5m/s²·yaw90°/s·pitch60°/s는 유지한다.

## 제어 조건

| 조건 | 실제로 변경하는 것 |
|---|---|
| heading | 이동 중 수평 속도 방향을 보며, 정지 후 배정된 관측 yaw로 회전한다. 회전 속도를 제한하고 관측 준비2초를 임무 시간과 계획 비용에 추가한다. |
| guarded | 1.25m 이하의 정지 발판을 비행 경로에 넣고, 지도 변경을1Hz로 확인한다. 새 장애물 앞에서는 현재 p/v/a와 연속인5차 감속 궤적을 만들어 관측된 FREE와 동료 예약을 검사한다. |
| look_step | 위 두 기능을 결합하고 공통 짐벌 범위를−0.8～+0.45rad로 넓힌다. 센서/점수에 같은 pitch를 제공하며 기존 회전 속도 제한을 유지한다. 이 더 넓은 범위를 갖는 가상 짐벌을 가정한 조건이다. |

guarded의 비행 지도는 각 복셀 중심뿐 아니라 복셀 안의 모든 위치에서 기체 반경과 여유가 유지되도록 voxel cube 사이 거리로 팽창한다. 이는 기존 모델에서 실제 충돌의 원인이 확인됐다는 주장이 아니라, 더 보수적인 여유를 시험하는 별도 이동 백엔드다. 실제 센서가 벽을 놓치면 여전히 충돌할 수 있다.

감속 궤적은 현재 속도·가속도를0으로 순간 변경하지 않는다. 다항식 극값으로 속도·가속도 상한을 확인하고, 좌표별 극값의 보수적인 구간 상자로 곡선 전체가 관측 FREE 안에 있는지 확인한다. 동료의 예정 궤적과 감속 이후의 정지 점유도 예약에 포함한다. 가능한 감속이 없으면 실패 이벤트를 남기고 실제 충돌 여부는 시뮬레이터가 판정한다. 참 지도로 위치를 고치거나 실패 기체를 재생성하지 않는다.

## 가치 조건과 비교

각 제어 조건에 동일하게 unknown, contact_v3 기반 entry progress, entry gain_rate를 실행한다. gain_rate는 기존의 `gain − 0.008×cost` 대신 실제 계획·대기·촬영·회전 준비를 포함한 `gain / cost`를 쓴다. gain은 관측 진행도 휴리스틱이며 보정된 성공 확률이 아니다. entry가 활성화되지 않은 경우의 미관측 탐색 대체도 기록한다.

첫 개발은 장면0/1/4/8·seed0·무연기/강한 저하의72회다. 학교16초의6개 연결 검사는 모두 실제 촬영212회·이동·충돌0·무효 안내0으로 완료했다. 이 짧은 검사로 목표 성능 향상을 주장하지 않는다. 저장 궤적과 실제 위치1,176개 및 카메라 회전 제한을 대조했고, 단위 검사39개가 통과했다. 같은 백엔드의 unknown 대비 무효 안내/차단 오판 수를 늘리지 않는 설정에서 균형 점수가 높은 설정을 선택한다. 전체 원래 unknown보다도 좋은지는 별도로 공개한다.

첫72회 결과를 보기 전에 추가 결합24회도 정의했다. 기존 순수 목적함수 실험에서 **개발만으로 선택한** 목적함수와, 위72회에서 선택한 제어를 결합해 unknown/progress/rate를 같은 개발 장면에서 실행한다. 선택한 목적함수·policy 소스는 기존 동결본의 바이트를 보존하고 후보 생성 함수의 AST가 같은지 확인한다. 주 실험의 검증seed2/3 결과는 읽지 않는다. 최종 개발96회에서 설정·수학 소스를 고정한 뒤 seed4 검증을 연다. 결합 실험이 더 좋지 않으면 기존 개발 설정을 유지하고 열세 결과도 남긴다.

검증은 결과를 보기 전에 seed4·기존10개 건물·두 센서 조건으로 고정했다. 선택된 동일 가치 함수를 기존 제어와 새 제어에 각각 적용하고 각 제어의 unknown을 함께 비교하는80회다. 이4조건으로 제어 효과와 가치 함수 효과를 구분한다. 기존 주 실험의 seed2/3 결과를 추가 조정의 입력으로 쓰지 않는다. 기존 라이브러리 건물이므로 완전히 새로운 건물 일반화라고 부르지 않는다.

## 소스와 재현

구현은 `covor/explore/flight_control.py`, 선택 분기는 `runner.py`이며 기본 동작은 유지한다. 설정은 `results/entry_control_20261109/configs/`에 있다. 수학 소스는 각 배치의 source_snapshot과 SHA256로 동결한다. 관측 깊이 NPZ·실제/추정 포즈·시각·지도·후보·배정·실제 제시 경로·감속 다항식·실패 이벤트를 보존한다.

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export COVOR_PY=/src/gs25058/miniconda3/envs/covor/bin/python
$COVOR_PY tests/test_flight_control.py -v
$COVOR_PY scripts/explore/entry_optimization_batch.py \
  --spec results/entry_control_20261109/gates_spec.json \
  --out results/entry_control_20261109/gates --workers 6 --global-limit 40
```

실제 완료 수와 수치는 배치 status.json과 실행별 summary.json에 있다. 이 문서는 실험 정의이며 실행 전의 성능 주장으로 쓰지 않는다. 오프라인 동기 시뮬레이션이므로1Hz 판정 주기가 실제 서버에서 실시간으로 달성된다고 주장하지 않는다.
