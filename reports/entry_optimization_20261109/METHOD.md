# Entry 목적함수 반복 개발과 고정 평가

> 2026-11-09 23:07 사용자 요청으로 이미 시작한 배치까지만 마친다. 순수 목적함수128회와 별도 조종/가치72회가 완료 대상이며, 이후 예정한 새 시드100회·결합24회·조종 검증80회는 실행하지 않는다. 아래에는 당시 계획도 보존한다. 실제 완료 결과는 [현재 범위 보고](current/RESULTS.md)에 분리한다.

목표는 같은 센서·비행·지도·사람 판정에서 유효 경로 확인과 올바른 차단을 늘리는 것이다. 이전40조건과 원본/실패 기록은 `fire_recon_20261108_resume`에 보존한다. 시간이나 토큰을 많이 쓰는 것을 성능 향상의 근거로 삼지 않는다. 현재 파일은 실행 방법이며 실제 결과는 완료된 실행만 별도로 기록한다.

## 고정한 항목

4대, 가상180초,4Hz, perfect_odometry,10개 기존 승인 복층 건물의 하부 층계참 보완본을 사용한다. unknown의 식·후보24개 생성·배정/예약/궤적·센서 오류와 연기장·적분·지지 증거/발 높이/자세/몸 공간/18cm 걸음·세 상태 판정·제시 경로의 독립 메시 검증·218개 목표를 유지한다. 목표와 분모를 결과에 맞춰 이동·제외하지 않는다. 최종 지도 생성 이후의 참 경로 탐색으로 제시 경로를 교체하지 않는다.

이번 변경은 config의 `utility.entry_objective`로 선택한다. 누락하면 기존 `legacy`가 유지된다. unknown은 새 목적함수 계산을 같이 하더라도 기존 미관측량의 추가 이득만 사용한다.16초 학교 clean 대조에서212개 관측, 지도12개 필드·궤적·실제 배정·사람 판정·경로와 운용 이벤트가 같았다. 새 entry 점수의 로그 칸이 달라지는 것은 허용한다. `validation/unknown_invariance.json`.

## 추가한 가치

기존 cut 기반의 완성 경로 중요도는 보존한다. 가능 경로 자체가 아직 생기지 않은 목표에도 관측 가치를 줄 수 있도록 다음을 더한다.

1. 확인된 입구 연결 영역 주변에서 다음 연결을 보완하는 국소 발판/몸 공간 관측.
2. 공개된 임무 목표 영역의 발판과 몸 공간, 관측된 부재/장애물 정보를 얻는 관측.
3. 현재 점유만 사용하는 거친3D 거리장으로 국소 관측이 어느 목표 쪽의 탐색에 해당하는지 추정.

거친 거리장은4복셀(40cm) 격자에서 관측 OCCUPIED를 max-pool해 가리고 미관측을 허용한다. 단차·발판을 확정하는 사람 경로망이 아니다. 거친 격자가 실제 좁은 문을 닫으면 낮은 가중의 공개 목표 거리 대체를 쓴다. 이 가설은 관측 가치에만 쓰며 통과/차단 판정과 지도에는 반영하지 않는다. 정책은 참 형상·깊이·오류 마스크·문/계단 목록·정답 라벨을 받지 않는다.

관측 가능성은 실제 공통 FOV/optical-Z 범위, 관측된 벽의 DDA 가림을 적용한다. 미관측 뒤 가시성은0.5배로 할인한다. 발판/몸 공간의 기존 증거와 예상 추가 증거를 결합해 두 비율 중 작은 값의 증가를 사용한다. 발판이 이미 확인된 경우에는 몸 공간만 보완해도 정보 증가가 있을 수 있다. 한쪽만 보이는 것을 경로 완성으로 계산하지 않는다.

`task_progress_v1`은 완성 중요도·국소 연결·목표 구역의 가중 합이다. `v2`는 같은 목표의 채널 최댓값, 남은 계획 거리의 할인, 실제 과거 추정 카메라 포즈에 따른 반복 시점 감점과 임무 종료 전 촬영 가능성 할인을 추가한다. 현재·과거의 관측만 사용한다. 시점 감점은45cm/45도 이내 과거1Hz 촬영 수를6초 단위로 세어 `max(0.05,1/(1+n/6))`이다. 같은 목표에 배정한 이득은 중앙 배정에서 최댓값을 빼 중복하지 않는다. 시간·발판 증거 수는 실제 촬영 그대로 계산한다.

## 개발과 검증 분리

사전에 저장한 `PROTOCOL.json`에서 개발 장면은0/1/4/8, 실행 seed0, clean/strong으로 고정했다. 첫 라운드는 bridge/mission/balanced × v1/v2의6개 설정, 총48회다.32초 학교 파일럿3회는 연결 검사이며 전체 성능이나 우승 설정의 근거로 쓰지 않는다. 모든 설정을180초까지 실행한다.

검증은 개발에 쓰지 않은 장면2/3/5/6/7/9와 새로운 실행/잡음 seed2로 고정한다. 기존 라이브러리 장면의 과거 결과는 이미 알려져 있어 완전히 처음 보는 건물이라고 부르지 않는다. 검증 결과를 보고 같은 검증에 맞춰 가중을 다시 고르지 않는다. 이후 재개발하면 이전 검증 실패를 보존하고 새 seed를 분리한다.

선택은 pooled 균형 판별 점수를 우선하되 paired unknown 대비 차단 오판과 무효 안내가 늘어난 설정은 따로 표시한다. 충돌·미확인·쉬운 한 점 경로도 모두 포함한다. 유효 경로/올바른 차단/무효 안내/판정률/거리/촬영/고장과 Pareto 대안을 함께 공개한다. 최대3개 개발 라운드를 먼저 정했으며 완료 수·실패·남은 조건을 구분한다.

## 실행과 보존

### 개발 중 추가 진단과v3

개발 장면인 학교의 첫 단절 연결을 자세히 확인했다. 양쪽 끝의 발판은 확인돼 있었지만, 대각선에 인접한 모서리의 자세·몸 공간이 미확인이었다. `validation/connection_audit.json`에 발판·높이·모서리 증거를 보존했다. 특정 기준 경로의 진단이며 모든 대체 경로에 대한 증명은 아니다.

v3는 최소 자세인 기기/옆으로 이동의 실제 몸 높이·폭 안에서 미확인 복셀을 추려 관측 대상으로 삼는다. 중심선이 모두 보여도 옆 공간이 미확인인 작은 지도 검사가 이를 검증한다. 몸 모델이나 판정 조건은 바꾸지 않았다. 목표 주변과 상부 약3m의 가설적 영역을 보는 enclosure 질의는 보수적인 차단 증명의 부족 정보를 수집하기 위한 값이며, 실제 방/문/천장 목록을 사용하지 않는다.

후보별 발판/몸 공간의 셀별 예상 증거를 여러 드론에 걸쳐 먼저 합집합으로 결합하고, 그 뒤 작은 쪽의 증가량과0.15배 부분 증거 진행도를 계산한다. 같은 셀/목표를 반복해서 세지 않으며, 발판만 보완하는 첫 관측과 몸 공간을 보완하는 두 번째 관측의 보완 효과를 허용한다. 이 예상값을 통과 확정 건수나 보정된 확률로 부르지 않는다. 실제 판정은 새 관측이 적분된 후 기존 Human에서만 수행한다.

contact/closure/joint의3개 가중 설정으로 개발 장면1/4·clean·64초의6개 파일럿을 시작했다. 이 결과로 전체180초의 성능이나 검증 성능을 미리 주장하지 않는다. v1/v2의48회는 동결 소스로 계속되며 v3를 소급 적용하지 않는다.

첫 기준 경로의 단절 연결 양끝은 실제 확인 탐색에서 모두 도달 가능했다. 즉 그 대각선 연결에는 확인된 우회가 있었다(`connection_audit_with_reachability.json`). 해당 첫 단절을 전체 목표 실패의 원인이라고 단정하지 않는다. 따라서 마지막 개발 라운드는 현재 관측 지지/벽/몸 공간 조건을 보존하면서 연속 미확인 길이 제한만 계획용으로 푼 경로를 추가로 찾는다. 주 판정기의 가능성 그래프와 확인 그래프는 바꾸지 않는다. 계획용 경로의 여러 직렬 미확인 구간은 목표 하나의 진행도 예산을 나눠 가지며, 한 구간의 관측을 목표 통과 확정으로 세지 않는다.

3라운드는 이 계획용 경로, 성긴 깊이 샘플의 발판 관측 가능성, 공개 오차 설정에 기반한 발 높이 정밀도 가중, unknown 탐색을 유지하며 entry 보너스를 더하는 혼합의7개 설정이다. 부모 가중은 완료한2라운드 개발 결과에서만 선택한다. 발판 품질 가중은 실제 오류·참 법선·참 연기 투과율을 쓰지 않는 근사이며, 기여하지 않으면 우승 설정에 포함하지 않는다. 수학 소스는 `planned_round03_source_v2`에 미리 동결했다. 총 개발128회 이후 설정과 수학 소스를 고정한다.

검증은 seed2에서10개 장면의 unknown/기존entry/선택entry60회, seed3에서 unknown/선택entry40회로 확장했다.6개 튜닝 제외 장면과4개 개발 장면을 나눠 보고하며, 두 시드 모두 실행 전에 고정했다. 결과를 본 뒤 같은 검증 시드로 추가 조정하지 않는다. 수학 소스는 선택된 라운드 사본을 그대로 가져오고 실행 CLI·검증된 native 호출 메모화만 별도 기록한다. 메모화의96개 native 입력/파생값과16초212관측 대조가 비트 동일했다. CPU 부하가 다른 실행의 벽시계로 속도 향상을 주장하지 않는다.

관측 위치가 같아도 기존 yaw로 몸 공간의 부족한 부분이 보이지 않는 한계는 공통 방향 보완 대조6회로 별도 평가한다. 위치·개수24·공통pitch·회전제약을 유지하고 두 정책에 같은 yaw 보완 절차를 제공한다. 이 대조의 결과를 원래 unknown과 비교해 목적함수만의 향상이라고 주장하지 않으며 순수 목적함수 우승 설정 선정에 섞지 않는다.

추가 실행 I/O 옵션 `--defer-dense`는 판정·배정·스냅샷·체크포인트·마지막 시각에서만 지도 배열을 새로 만들고, 쓰이지 않는 중간 배열 변환을 생략한다. OctoMap의 `updateInnerOccupancy`는 원래 호출마다 그대로 실행하며 촬영·적분을 생략하지 않는다. unknown16초212관측 중8초 중단/재개 대조와 entry_v4의16초212관측 대조에서 지도12필드, 궤적·운용 이벤트·판정·경로·실제 배정이 정확히 같았다. entry 대조는 후보/점수 로그도 같았다. `validation/deferred_dense_invariance.json`, `validation/entry_v4_deferred_invariance.json`. 이미 실행 중인1/2라운드는 중단하지 않았고3라운드와검증의 모든 정책에만 같은 옵션을 적용한다. 기본값은 꺼져 있으며 실행 도우미 해시도 저장한다. 부하와 깊이 재생 여부가 다른 대조의 벽시계로 가속 배율을 주장하지 않는다.

`entry_optimization_batch.py`는 매 라운드 소스 사본과 해시를 동결하고 자식 실행이 그 사본을 import하게 한다. 다음 구현을 수정해도 이미 진행 중인 실험 소스는 바뀌지 않는다.8초마다 확률/표면/기체/로그 체크포인트를 저장해 중단 후 동일 소스/설정으로 이어간다. 기존 실험을 덮어쓰지 않는다.

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export COVOR_PY=/src/gs25058/miniconda3/envs/covor/bin/python
$COVOR_PY tests/test_entry_objective.py

  --spec results/entry_optimization_20261109/round01_spec.json \
  --out results/entry_optimization_20261109/round01 --workers 32
```
