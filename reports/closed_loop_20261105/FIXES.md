# 발생 조건과 수정 이력

방법별 승패를 보고 보상을 조정하지 않았다. 다음은 입력/출력·평가·공통 이동 계약의 실패를 바로잡은 기록이다. 결과가 완성된 각 단계는 별도 경로에 보존했다.

| 단계 | 실제 실패/한계 | 적용한 수정과 경계 |
|---|---|---|
| 생성 검증 | 입구 x=2.00 부근의 좁은 영역에 0.1 m voxel 중심이 없어 기준 시작 노드가 0 | 방법 실행 전 x=2.05, y=0.65의 고정 구역으로 정함. 모든 방법·정답 동일, 임의 snap 없음 |
| 완전 지도 v1 | 셀 중심만으로 벽 점유를 만들자 문틀을 일부 포함한 셀이 FREE가 되어 제시 경로가 메시와 충돌 | 기준 voxel은 상자와 셀 부피의 교차로 생성. 독립 상자 정답은 그대로이며 목표 4/3 도달 라벨 불변. `validation/truth`, `truth_v2` 실패도 보존 |
| 양성 대조 | 정확히 벽에 접하는 몸 외곽에서 raycast t=0이 충돌로 집계 | 새로운 평가 설정에서만 1 mm 접촉 허용을 명시. 옛 평가 기본값 0 유지. 이후 양성 대조와 생성 경로 모두 통과 |
| 시작 발 높이 | 관측 표면의 평균과 부피 셀 경계가 다름 | 새 Human 어댑터에만 측정 높이+0.025 m offset 전달. 기존 DecisionGraph 기본 0.005 m 유지; 새 범위를 설정/경로에 저장 |
| 단일 관측 vs 표면 2회 | 한 번만 촬영한 지지가 확인되지 않음 | 임계치를 낮추지 않고 실제 1초 주기 영상과 6초 도착 촬영을 실행. 프레임 고유 ID와 map version 기록 |
| 초기 관측 자세 | 미관측량만 따르면 상부 촬영이 많고 발판 증거가 부족 | 두 방법 모두 같은 물리적 6초 짐벌 하부/상부 스캔. pitch 속도 제한과 실제 자세 CSV 기록 |
| 실외로 향하는 unknown 가치 | 공통 대기 공간 밖의 실외 미관측량을 탐색 이득으로 셈 | 동일한 알려진 건물 외곽의 탐색 범위만 이득으로 계산. 내부 문/방/바닥 정답은 쓰지 않음 |
| 두 기체 v1 | 동료 잔상 및 예약 검사만으로는 정지한 동료를 우회하지 못해 이동 정체 | 원래 동료 제외 반경 0.35 m 복원. 정지 동료·예약 종점은 관측 FREE A*에서도 피함. 재실행 이동 8.88 m 합계, 충돌 0 |
| 주 비교 v1 (`main`) | 미관측 점수로 경로 검사 대상 5개를 추려 entry 후보를 가치 비교 전에 배제할 수 있음 | v2부터 최대 24개 공통 후보 전부 이동 검사. 연결 성분의 도달 불가 빠른 제거만 허용. v1 전체는 보정 전 진단으로 별도 보고; 최종 비교는 동일 v3 버전의 모든 성공/실패 실행을 포함 |
| 가시성 v1 | helper의 5 m 상수가 센서 4.5 m 범위와 다름 | 기존 helper에 기본 5 m를 유지하는 선택 옵션 추가; 새 두 정책만 실제 센서 범위 전달 |
| 주 비교 v2 (`final`) | 연기 scene11/seed0, 28.5초에 새 점유로 중간 정지한 드론과 다른 기체가 충돌 | 정지 후 무기한 hover까지 모든 기존 예약에 대해 검사하고 안전한 원래 정지점만 선택. 중간 정지만 추가하면 충돌하는 단위 사례 추가. v2 실패 실행을 보존하고 v3 두 정책 모두 재실행 |

최종 v4도 SGBM이 실제 벽을 FREE로 잘못 만드는 센서 실패까지 참 지도로 미리 막지는 않는다. 참 형상 충돌은 시뮬레이터가 결과로 판정하고, 충돌 기체는 마지막 안전 위치에 고정하며 나머지만 계속 운용한다. 충돌이나 미확인 결과를 숨기거나 드론을 재생성하지 않는다. 다음 정지점까지의 동기식 운동학 모형이며 완전한 비상 제동 제어기나 고장 안전 인증은 아니다.

기존 `covor/entry/traverse.py`의 면적 score와 틈/스냅 기본값은 이번 작업에서 변경하지 않았다. 작업 시작 전부터 있던 predecessor 출력 변경도 보존했다. 새 목표·경로 지표는 별도 어댑터와 CSV다. `DepthRenderer(calib=...)`, `DecisionGraph(foot_contact_offset=...)`, `PathEvalCfg`의 step/contact 옵션, visibility의 max_range 옵션은 모두 옛 기본 실행을 유지하는 추가 인터페이스다.

배정 데이터 최신성 추가 수정: v3까지는 평가 저장 주기(4초)의 진입 그래프를 2초 배정에서 재사용해 최대 2초 전 상태로 entry 영향을 계산할 수 있었다. v4는 배정 전 `ensure_current_analysis`로 지도 버전을 확인하며, 활성 작업도 현재 지도에서 다시 점수화한다. 두 방법에 같은 계산 절차를 적용하고 효용 수식이나 목표·시드·예산은 바꾸지 않았다. 이 수정의 검증은 `test_entry_graph_refreshes_on_map_version_before_assignment`이며 v3 결과 전체도 보존했다.
